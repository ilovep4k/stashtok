1 · Shell and navigation model

StashTok is mounted as a page inside Stash (/stash-tok). It replaces Stash's page body but not its chrome, so there are two navigation layers to keep straight: Stash's own sidebar on the left, and StashTok's own bottom bar / drawer.

FeedDefault landing. Vertical player, endless pool.
DiscoverPerformer cards, random/trending entry points.
PerformersSearchable index of every performer.
FavoritesEverything rated ≥ heart threshold.
TagsTag grid, counts, tap → tag feed.
MarkersMarker feed grouped by tag.
SearchType-ahead over scenes and performers.
SettingsPreferences, feeds, privacy lock, ops.

Bottom bar (primary)

Fixed Feed button plus four configurable slots. Defaults: Discover · Performers · Favorites · Settings. Long-press the last three to repoint them. Hidden on drill-downs (performer page, folder page, feed opened from a profile) so it never sits on top of the content you came for.

Drawer (secondary)

The top-left menu button opens every destination, including Markers and Search, which have no bottom slot by default. It is the stable map; the bottom bar is the shortcut layer. Title reads StashTok so the drawer matches the product, not the host instance.

Tab blur with a PIN set black-screens the app and asks for the PIN on return. Without a PIN, playback pauses and resumes where it stopped.

4 · UI consistency audit

Fixed in this pass, all verified against the live app at 1440×900 and 430×932:

FindingBeforeNowStatus
Hover preview blanks tiles Pointer resting on a tile mounted a stream that replaced the still with a blank frame; arrow-key traversal looked like tiles vanishing. Preference forced off once per browser; hover is inert until explicitly enabled. Fixed
Duplicate “Folders on top” Same preference rendered twice — once under Performer page, once under a “Folder view” heading that no longer described it. One row, under Performer page, where the grouping actually happens. Fixed
Empty setting hints “Show Images tab” and “Show Markers tab” had no explanation while every neighbour did. Both state what the tab adds and where. Fixed
Hover hint copy “Playing the clip when the pointer rests on a tile…” — fragment, and it promised behaviour the file cannot deliver on libraries without previews. “Plays the clip's own file… Off by default — it streams the real file and is heavy for a decoration.” Fixed
Two default nav configurations Base defaults ended in Tags; the migration reset ended in Settings. Which one you got depended on when you first loaded the plugin. Single default: Discover · Performers · Favorites · Settings. Fixed
Drawer branding Hardcoded personal instance name in a plugin drawer. Product name, consistent with the plugin manifest. Fixed

Open recommendations, not applied:

AreaObservationRecommendation
Hover previews, when re-enabled The reveal gate is loadeddata + videoWidth > 0. A decodable but black first frame still counts as ready. Reveal only after timeupdate shows playback has advanced, or sample the frame and skip all-black. Otherwise leave the feature off.
Case conventions Section headers are Title Case; row labels are sentence case. Consistent within each layer, but undocumented. Write the rule at the top of the settings component so new rows don't drift.
Destructive controls “Remove” (PIN) is the only red button; “Reset” (bottom bar) is neutral though it discards layout choices. Treat both as destructive: outline-danger, or confirm-on-tap.
Keyboard discovery Arrow keys, Enter, and hold-to-FF exist but are not surfaced anywhere. A small “Keyboard” block in Settings, or a ? overlay on the grid.
Selection ring on bright stills White 3px ring can disappear on a white thumbnail. Add a dark inner ring (already present) and confirm contrast in both themes.
Settings discoverability Reachable from the bottom bar by default, but the label is icon-only at narrow widths. Keep the gear in slot 4; the drawer row remains the labelled path.
